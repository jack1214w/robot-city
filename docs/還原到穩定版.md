# 怎麼還原到穩定版

有**兩個**還原點，看你要回到哪一個：

| 名字 | 是什麼 | 在哪個分支 | 離線備份資料夾 |
|---|---|---|---|
| **`v1.0`** | 平板連線動工前的單機版（單人練習 ＋ 單機熱椅） | `main` | `robot-city-備份-v1.0` |
| **`v1.1`** | **平板連線可用**。2026-11-18 在教室用三台裝置跑過 | `live-mode` | `robot-city-備份-v1.1` |

**平常要回到的是 `v1.1`。** 它包含 `v1.0` 的全部功能，再加上平板連線。
只有在「連平板連線本身都想拿掉」的時候才回 `v1.0`。

下面的指令把 `v1.0` 換成 `v1.1` 就是還原到平板連線版，用法完全一樣。

---

## 情況 A：上課前十分鐘，程式壞了，沒時間弄 git

**直接用桌面上的離線備份。**

```
CC工作區/Code專屬/robot-city-備份-v1.1/index.html
```

雙擊它就能玩，**不需要網路、不需要 git、不需要我**。
同一個資料夾裡也有帶班速查表和學生簡報。

這份備份是直接從 `v1.1` 標籤取出來的，已逐位元組比對確認與標籤一致。
要讓學生用平板連線，雙擊同一個資料夾裡的「平板連線-啟動.command」。

（`robot-city-備份-v1.0` 也還在，是更早的單機版。）

---

## 情況 B：想把程式碼還原回穩定版

### 先看一下現在跟穩定版差在哪

```bash
cd ~/Desktop/CC工作區/Code專屬/robot-city
git diff --stat v1.0
```

沒有輸出就表示**目前跟穩定版一模一樣**，不用還原。

### 只還原某一個檔案

例如只有遊戲壞了，文件不想動：

```bash
git checkout v1.0 -- index.html
```

### 全部還原

```bash
git checkout v1.0 -- .
```

這兩個指令都**只改檔案，不動提交紀錄**，所以很安全，改完不滿意還能再改回去。

### 如果壞的版本已經推上 GitHub 了

```bash
git checkout v1.0 -- .
git commit -m "還原到 v1.0"
git push
```

等一兩分鐘，GitHub Pages 會重新部署，線上版就回到穩定版了。

## 關於那份簡報，有件事要記住

`機器人蓋城市-遊戲規則.pptx` 是**產生出來的檔案**，原始碼在 `tools/deck/gen.js`。

**用 PowerPoint 開著它的時候，不要做版本控制。**

2026-11-17 發生過一次：簡報在 PowerPoint 裡開著，存檔時把記憶體裡的舊內容寫回去，
蓋掉了剛產生的新版，然後被一次 `git add -A` 連帶提交、推上線，線上版退回舊版。
後來從前一個提交還原才救回來。

要改簡報內容，改 `tools/deck/gen.js` 然後重新產生，不要直接編輯 pptx——
下次重新產生就會蓋掉你的手改。做法見 `tools/deck/README.md`。
